VinePalmaFlow 本機專案管理

🚧 迭代中📅 2026
#Tauri#Rust#專案管理#區域網路同步

VinePalmaFlow 的口號是「永遠不上雲，但在區域網路裡像雲一樣協作」。它是一款本地優先（Local-first）的專案管理桌面應用，基於 Tauri 2 + React + Rust 構建：零帳號、零上傳，所有專案資料只留在你自己的裝置上；當兩臺裝置處在同一區域網路時，又能通過加密配對實現增量同步——雲的體驗，沒有雲的隱私代價。

設計哲學：Markdown 檔案就是資料庫

大多數專案管理工具把你的資料鎖進專有資料庫，而 VinePalmaFlow 的唯一事實源是人可讀的 Markdown 檔案。每個專案是一個資料夾：project.md 用 YAML Front Matter 描述後設資料（名稱、狀態、負責人、截止日、進度、標籤、自定義欄位……），正文就是普通 Markdown；tasks/ 目錄下每個任務一個原子檔案；附件、模板、備份、資源回收筒各歸其位。哪怕有一天你解除安裝了 VinePalmaFlow，這些檔案依然可以用任何編輯器開啟、用 Git 管理、用指令碼批次處理。

新手可以完全通過表單操作，不必知道 Front Matter 的存在；進階使用者則可以直接改檔案，應用會忠實地解析回來。表單與文本兩種心智模型，指向同一份資料。

區域網路同步：mDNS 發現 + TLS 加密 + 6 位配對碼

同步是整個專案技術含量最高的部分。裝置發現基於 mDNS（服務型別 _localflow._tcp.local.，預設埠 4485），傳輸層是 TLS 1.3 之上的 WebSocket。難點在於區域網路裡沒有 CA、沒有域名——我們用自簽證書承載裝置身份，真正的認證下沉到應用層：兩臺裝置各自螢幕上顯示一個 6 位配對碼，互相輸入對方螢幕上的碼，雙向核對通過後才把對方寫入信任列表。此後每次連線，服務端都會從對方的 TLS 客戶端證書裡解析出裝置 ID，凡是不在信任列表裡的推送一律拒絕——偽造訊息體裡的身份是過不了關的。

這中間踩過的 rustls 0.23 的坑（crypto provider 安裝、IP 直連的 SNI 構造、證書有效期的時鐘偏移），我們單獨寫成了部落格《沒有 CA 的區域網路，怎麼做雙向 TLS》。

增量同步與衝突合併

全量互傳太浪費，VinePalmaFlow 為每個專案計算內容指紋（project.md + 排序後的任務檔案，手寫 FNV-1a 雜湊）。同步時先交換指紋表，相同的直接跳過，只傳有差異的專案。合併採用三方合併：每個裝置目錄下儲存著上次同步的基準映象，本地版本、對方版本、基準版本三者對比——單邊修改直接採納；雙邊都改了同一個欄位才判定衝突。

更精細的一層是 project.md 的欄位級合併：A 裝置改了進度、B 裝置改了正文，整檔案對比會誤判衝突，而按 YAML 欄位逐個三方合併後，兩處修改可以自動合併成一份。真正的衝突會進入 UI，由使用者二選一，選擇結果同時寫回基準映象——否則同一個衝突會在下次同步時無限復活。

匯出：Excel 不是終點，而是入口

匯出用 rust_xlsxwriter 實現，匯入用 calamine 讀回。我們不滿足於"把任務表丟進 Excel"：概覽頁帶條件格式（已完成綠、進行中黃、已延期紅），進度列用百分比數字格式；更關鍵的是第 4 個 Sheet 嵌入了完整的 YAML Front Matter 與 Markdown 原文——匯出再匯入，資訊零損失，真正意義上的無損往返。此外還支援 CSV、JSON，以及用 pulldown-cmark 渲染的 HTML（方便瀏覽器列印成 PDF）。

周邊能力

模板系統：內建軟體開發、客戶跟進漏斗等模板，模板定義的列表型欄位存進 custom_fields，匯出任務明細時自動提取；全文搜尋：線性掃描 + 大小寫摺疊，單機幾百個專案規模下足夠快；變更日誌：欄位級 diff 追加儲存，保留 30 天、上限 2000 條；每次儲存自動生成舊版本快照，配合資源回收筒，誤刪誤改都有後悔藥。

工程取捨

PRD 裡原本規劃了 tokio 非同步堆疊，實際落地時我們選擇了 std::thread + 同步版 tungstenite——單條 JSON 請求-響應、裝置數量個位數的場景，引入非同步執行時的複雜度並不划算。類似的取捨貫穿全專案：不用 apt 庫、不用 YAML 庫做序列化（手寫固定欄位順序的冪等輸出）、不用非同步 mDNS（零conf 庫同步 API）。Rust 的好處就是這些"降級"都不犧牲型別安全。

結語

VinePalmaFlow 目前仍在快速迭代，藍牙備用通道、更多模板還在路線圖上。如果你受夠了把任務清單交給別人的伺服器，不妨試試這株只生長在自己裝置上的藤蔓——資料在哪裡，安全感就在哪裡。
