VinePalmaUninstaller卸载器软件开发

在 Linux 系统上卸载软件，从来不是一件轻松的事：APT、Flatpak、Snap、Docker、AppImage……不同来源的软件要记不同的命令，而手动安装的软件更是根本不在包管理器的"户口本"里。更让人头疼的是，即便用 apt purge 卸载干净，~/.config、~/.cache、~/.local/share 里仍会残留一大堆配置文件，日积月累占满磁盘，却往往只换来一句"卸载失败"或"已卸载但残留未清除"。

因此，我们 VineTurtleStudio 开发组设计并开发了这款 Linux 卸载器，使用 Tauri + Vue 进行开发，把 APT、Flatpak、Snap、Docker、AppImage 与 APM 六大来源的软件统一纳入一个图形界面，在"彻底卸载"与"绝不误删"之间找到平衡。

项目背景与目标

Linux 的软件生态百花齐放，却也带来了管理的碎片化：系统自带的应用商店只能管理一种来源；命令行又要求用户记住各不相同的卸载语法；而 Debian 系安装包卸载后遗留的 "rc 状态"（配置文件记录），类似 Windows 的注册表残留，普通用户几乎无从下手。我们希望打造一款面向普通用户的图形化卸载器：一次扫描，六大来源尽收眼底；点击卸载之前，先用模拟预览告诉你会影响什么；勾选残留文件，一并清理干净——全程无需命令行，也绝不乱删系统组件。

技术架构

VinePalmaUninstaller 采用 Tauri 2 作为应用框架，前端使用 Vue 3 + Vite，后端使用 Rust 提供原生能力。所有与系统交互的扫描、模拟与卸载逻辑都写在 Rust 侧：通过 dpkg-query、flatpak list、snap list、docker images 等命令聚合各来源的已安装软件，需要 root 权限的操作（如 apt purge）通过 pkexec 动态提权，普通用户也能在界面里完成系统级卸载。

后台进程统一使用 tokio 异步执行，并带有超时保护，避免个别卡死的命令阻塞整个界面；涉及删除的操作会先走"服务端生成计划 → 前端勾选 → 服务端白名单校验"的流程，可删除的路径只来自服务端重新生成的计划，杜绝提交任意路径造成误删。

核心能力：六大来源统一扫描

APT：通过 dpkg-query 读取全部已安装包及其大小、描述，并利用 /var/lib/dpkg/info 下 .list 文件的修改时间近似估算安装时间，默认隐藏系统库、内核与依赖；Flatpak 与 Snap：分别调用对应包管理器列出应用，安装时间与大小通过应用目录与 snap 文件的元数据解析；Docker：扫描本机镜像，可解析镜像大小与创建时间，卸载时还会自动先删除引用该镜像的容器；AppImage 与手动安装：这类软件没有包管理器登记，我们通过扫描 ~/Applications、/opt 等常见目录中的 AppImage 文件，并结合 .desktop 启动项中 Exec 指向手动安装路径的条目来识别；APM（Amber Package Manager）：从容器内的 dpkg 状态文件解析安装信息，再通过 /usr/local/share/applications 下 "apm run <pkg>" 形式的桌面入口把界面启动项与容器内数据一一对应起来。

风险等级与用户级过滤

我们并非靠"猜包名"判断危险程度，而是直接解析 /var/lib/dpkg/status 与 extended_states 的真实数据：统计每个包被多少已安装包反向依赖、标记 Essential 与 required 优先级的系统生死攸关组件。基于这些数据，每个软件都被打上 low / medium / high / critical 四档风险标签：Essential 或 required 优先级的包即为核心（critical），被 8 个以上包依赖的为高风险，GUI 应用则默认低风险。界面默认的"简易模式"只显示用户级软件（有图形界面入口的包），系统库、内核、命令行工具一律隐藏；"高级模式"才展示全部软件并标注风险等级，卸载前还会有醒目的风险横幅与连带影响警告。

卸载计划：先预览，再执行

点击卸载并非直接执行命令，而是先由服务端生成一份完整的卸载计划：对 apt 包，先以模拟模式运行 apt-get purge，解析出会被移除的包列表——如果会连带移除其他相关组件，会在计划中明确警告"还会连带移除 N 个相关包"；执行时则带上 AutomaticRemove=0 选项，绝不让 apt 自动连带移除依赖，只动目标包本身。计划中还会列出每一条将执行的命令、是否需要授权，并把残留文件按配置 / 缓存 / 数据 / 系统分类展示，勾选才删除、不勾选保留，用户对每一步都有完全的掌控。

残留清理与孤儿依赖

针对"卸载不彻底"的痛点，我们做了两件事：一是识别 dpkg 中已卸载但留下配置记录的 "rc 状态" 包，一键 dpkg --purge 彻底清掉残留记录；二是为每个软件扫描常见的独立存放目录（~/.config、~/.cache、~/.local/share、~/.local/state、~/Applications、/opt），通过"包名变体匹配"识别出软件自己的配置目录——大小写不敏感、连字符/下划线等价，避免默认路径冲突导致的"换名存放"。精确命中的目录默认勾选，仅"包含"关系的模糊命中默认不勾选，绝不误删无关软件。此外还内置了孤儿依赖清理：先预览 autoremove 将移除的包，确认后再执行。

安全设计：绝不误删

作为一个会删除文件的工具，安全性是我们的底线。除了"计划即白名单"的机制外，后端还有多层防护：FORBIDDEN 路径表拦截 /、/home、/etc、/usr、/var 等系统关键目录及其直系子目录；禁止删除 home 下的 .config、.cache、.local 等受保护根目录；拒绝含 .. 等危险组件的路径；支持"保留用户配置"与"保留系统配置"两种保护开关，用户勾选的路径若落在系统目录可被即时过滤。每次卸载完成后还会重载 dpkg 数据库缓存，确保重装后的软件也能被正确识别，界面数据永不过期。

体验细节

界面采用深色主题：列表按名称 / 安装时间 / 占用大小 / 风险等级排序并可切换升降序，支持关键词搜索与按来源过滤；每个软件都尝试从 dpkg 文件清单、图标主题、Flatpak/Snap 导出目录乃至 APM 容器内图标树中解析出真实的应用图标；顶部展示当前发行版与架构，卸载残留页有独立的数量角标，操作完成后有 Toast 反馈并自动刷新列表。图标解析还做了多级缓存与批量化加载，扫描上千个包也不会卡顿。

踩过的坑

开发中踩了不少 Linux 生态的坑：apt-get 的模拟输出在不同版本间存在 "Removing" 与 "Purg" 两种前缀，需要同时兼容解析；purge 与 --no-install-recommends 组合会报 "not understood" 错误，必须调整参数顺序与选项；dpkg 输出中包描述里可能内嵌换行导致解析错乱；docker 镜像大小带 GB/MB 后缀、flatpak 的 size 带千位分隔符，都需要逐一编写解析器；图标模糊匹配要小心泛化目录名误命中，短于 3 个字符的图标名一律不参与匹配。这些坑我们都通过单元测试固化了下来，作为回归保障。

跨平台与打包

项目基于 Tauri 2 构建，打包产物为 deb 与 AppImage，前者声明了 libwebkit2gtk-4.1 与 libgtk-3 的依赖，并提供了自定义的桌面入口模板；前端由 Vite 构建，Rust 后端编译为原生二进制，整个应用启动快、内存占用低，不依赖 Electron 之类的重型运行时。

结语

VinePalmaUninstaller 目前处于 1.0.0 版本，作为 VineTurtleStudio 的开源项目，我们希望通过它证明：Linux 卸载软件也可以像移动端一样直观、安全、不留尾巴。后续计划继续扩展更多发行版与包管理器支持、完善残留识别的覆盖面，欢迎大家在 GitHub 上提出建议，一起把它做得更好。
