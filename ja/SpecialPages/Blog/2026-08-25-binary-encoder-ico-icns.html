ブラウザで手書きするバイナリエンコーダー：ICO / CUR / ICNS を組み立てる

📅 2026年8月25日🕐 約 5 分
#フロントエンド#バイナリ形式#VinePalmaToolbox#落とし穴

VinePalmaToolbox の「画像形式変換」ツールを作っていて、気まずい事態に遭遇しました：ブラウザ Canvas の toBlob() が対応しているのは PNG / JPEG / WebP だけなのに、ユーザーが最もよく求めるのは「この画像を ICO アイコンに変換して」。npm を漁っても使える ICO エンコーダはほとんどなく、ICNS（macOS のアイコン形式）に至っては、保守された純フロント実装が皆無でした。最終的な決断：フォーマット仕様に沿って、DataView で 1 バイトずつ自力で組み上げる、でした。

🧱 ICO：最も「単純」なコンテナ形式

ICO の本質は「PNG パッケージャ」です：ヘッダ + ディレクトリ + 画像データ。Vista 以降は PNG データの直接埋め込みが許され、実装は大きく簡素化されました——Canvas で元画像を各サイズに縮小して PNG を書き出し、あとは組み立てるだけ：

// 文件头：6 字节，小端
writeU16(0);        // 保留字段，必须为 0
writeU16(1);        // 1 = ICO，2 = CUR
writeU16(count);    // 目录项数量

// 每个尺寸一个目录项：16 字节
writeU8(size === 256 ? 0 : size);  // 宽（256 写 0！）
writeU8(size === 256 ? 0 : size);  // 高
writeU8(0);          // 调色板数
writeU8(0);          // 保留
writeU16(1);         // 色彩平面（ICO）
writeU16(32);        // 色深
writeU32(png.length);// 数据长度
writeU32(offset);    // 数据偏移

転びやすい 3 つの細部：① 256px の幅と高さは 256 ではなく 0 を書く（1 バイトには収まらないため、仕様は 0 を 256 と約束）；② オフセットは累積計算で、ディレクトリ領域の直後にある最初のデータブロックのオフセットは 6 + 16×count；③ ICO と CUR の違いはタイプフィールドだけではなく、CUR はさらに「カラープレーン/色深度」フィールドをホットスポット座標（hotspot x/y）に書き換えます——マウスカーソルのクリック位置はまさにこの 2 フィールドに格納されるのです。

🍎 ICNS：ビッグエンディアンの別世界

ICNS は macOS のアイコン形式で、ICO との最大の違いはビッグエンディアンであること、そして 4 バイトの ASCII タイプコードでサイズを識別すること：

writeU32(0x69636e73);  // 'icns' 魔数（大端）
writeU32(totalLength); // 整个文件长度
// 每个尺寸一个块：
// 4 字节类型码 + 4 字节块长 + PNG 数据
writeType('icp4');   // 16x16
writeType('ic07');   // 128x128
writeType('ic10');   // 512x512（或 1024@2x）

デバッグで最も時間を食ったのは「ファイル長」フィールドです：全ブロック長の合計 + 8 バイトヘッダと等しくなければならず、1 バイトでも間違えると macOS は読み込みを拒否します——しかもエラーを一切出しません。

🔍 通用の経験：十六進エディタで受け入れ検証

バイナリコードの正しさは console.log では見えません。私たちの受け入れフローは：ファイル生成 → xxd で先頭 16 バイトを確認 → spec の各フィールドと突き合わせ → システムツール（file コマンド、macOS プレビュー、Windows エクスプローラー）でクロス検証。file x.ico が "MS Windows icon resource - 5 images" と出力したあの瞬間は、どんなユニットテストよりも安心できます。

📝 まとめ

この手作りで得たもの：バイナリ形式は想像ほど神秘ではありません——ICO は「配列 + オフセット」、ICNS は「TLV リスト」で、本当の作業量は境界の約束事（256 は 0 と書く、長さにヘッダを含むか否か、ビッグ/リトルエンディアン）にあります。こうした約束事は spec の中でたいてい半文程度しかないのに、落とし穴は全部そこに宿っています。VinePalmaToolbox の画像変換ツールは現在 PNG/JPEG/WebP/BMP/ICO/CUR/ICNS/DDS の相互変換に対応し、コアのエンコードロジックは全部で 400 行の TypeScript に収まっています。
