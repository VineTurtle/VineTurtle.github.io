純靜態網站的四個經典坑

📅 2026年8月25日⏱ 約 5 分鐘
#JavaScript#CSS#GitHub Pages#踩坑

葡葉醬的溫暖小窩（GrapeLeafi）是我們維護時間最長的專案：一個沒有框架、沒有構建、沒有後端的純靜態粉絲站。正因為它「誰都能改」，幾年間積累了一堆靜態站的典型 bug。這四個坑每一個都簡單到不值一提，卻又每一個都真實地在線上存活了很久。

坑一：永不觸發的「今天過生日」

站點有個角色生日提醒功能，程式碼裡明確寫著慶祝分支：

if (diffDays === 0) {
    // 🎉 今天生日！撒花
}

但這個分支從未被執行過。根因在上游的日期比較：

birthdayDate.setFullYear(today.getFullYear());
if (birthdayDate < today) {      // ← 问题在这
    birthdayDate.setFullYear(today.getFullYear() + 1);
}
const diffDays = Math.ceil((birthdayDate - today) / 86400000);

today 是 new Date()——帶當前時刻（比如 14:30），而 birthdayDate 被設定為生日的零點。生日當天零點必然早於 14:30，於是日期被推到明年，diffDays 變成 364——「今天」永遠顯示成「還有 364 天」。這是「時刻」與「日期」比較的經典混淆。解法是把兩邊都歸零到當天零點，再判斷是否同一天：

const startOfToday = new Date();
startOfToday.setHours(0, 0, 0, 0);
const isToday = birthdayDate.getTime() === startOfToday.getTime();

坑二：手機上永遠彈不出的二維碼

QQ 群二維碼用的是純 CSS 方案：

.qrLinkContainer:hover #qrCodeContainer { display: block; }

桌面端體驗完美，但觸控裝置沒有 hover——手機使用者點按鈕毫無反應，加群入口直接消失。這是純 CSS 互動的天然盲區。解法是補一個 click/touch 切換 class 的兜底，或者用原生 <details> 元素實現「點開顯示」，零 JS 也能在觸控裝置正常工作。

坑三：GitHub Pages 的大小寫與特殊字元 404

資源目錄裡混著歷史遺留命名：tuan-zi/团子 (1).ico——中文、空格、括號三件套，favicon 引用不得不寫成 团子%20(1).ico。Windows 本地預覽一切正常（NTFS 大小寫不敏感），一推到 GitHub Pages（Linux 伺服器，大小寫敏感），任何一次「順手改個路徑大小寫」都會批次 404。教訓是：靜態站資原始檔名一律小寫 ASCII、連字元分隔，中文素材名在入庫時統一重新命名。另外目錄裡 tuan-zi/ 與 tuanzi/ 並存這種「歷史改名殘留」，也該趁早清理。

坑四：CDN @latest 是定時炸彈

Live2D 看板娘是這樣引入的：

<script src="https://fastly.jsdelivr.net/gh/stevenjoezhang/live2d-widget@latest/autoload.js" defer></script>

@latest 意味著上游每次提交，你的站點都在「抽獎」：上游改了介面，全站看板娘原地消失，而你可能毫不知情。靜態站引用第三方 CDN 資源必須鎖定版本號甚至 commit hash。順帶一提，站點的倒計時用 setInterval(update, 86400000) 每天重新整理一次——如果頁面跨午夜一直開著，倒計時會顯示過期資料；改成每分鐘重新整理或監聽 visibilitychange（頁面重新可見時更新）更穩妥。

📝 寫在最後

這四個坑的共性：在開發者的裝置上永遠復現不了。生日 bug 只在生日當天出現、hover 問題只在觸控裝置出現、大小寫 404 只在 Linux 伺服器出現、@latest 只在上游更新時爆炸。靜態站雖小，測試矩陣卻橫跨時間、裝置與作業系統。維護老站點的正確姿勢，就是把這些「低階」坑一個個記錄下來——它們是最便宜的老師。
