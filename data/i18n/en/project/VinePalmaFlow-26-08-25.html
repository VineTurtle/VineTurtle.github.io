VinePalmaFlow's slogan is "never touch the cloud, yet collaborate over LAN like the cloud". It's a local-first project management desktop app built on Tauri 2 + React + Rust: zero accounts, zero uploads, all project data stays on your own devices; when two devices share the same LAN, encrypted pairing enables incremental sync — the cloud experience, without the cloud's privacy price.

Design philosophy: Markdown files are the database

Most project management tools lock your data inside a proprietary database; VinePalmaFlow's single source of truth is human-readable Markdown files. Each project is one folder: project.md describes metadata in YAML Front Matter (name, status, owner, deadline, progress, tags, custom fields...), and the body is plain Markdown; under tasks/, every task is one atomic file; attachments, templates, backups and the trash each sit where they belong. Even if you uninstall VinePalmaFlow one day, these files still open in any editor, live happily under Git, and can be batch-processed with scripts.

Beginners can work entirely through forms without ever knowing Front Matter exists; power users edit the files directly and the app faithfully parses them back. Two mental models — form and text — pointing at the same data.

LAN sync: mDNS discovery + TLS encryption + a 6-digit pairing code

Sync is the most technically dense part of the project. Device discovery is mDNS-based (service type _localflow._tcp.local., default port 4485); the transport is WebSocket over TLS 1.3. The hard part is that a LAN has no CA and no domain names — we carry device identity on self-signed certificates and push real authentication down to the application layer. Each device displays a 6-digit pairing code on its screen; each side types in the code shown on the other's screen, and only after a two-way check does the peer enter the trust list. From then on, at every connection the server parses the device ID out of the peer's TLS client certificate, and any push whose ID is not in the trust list is rejected flatly — a forged identity inside the message body never gets past the gate.

The rustls 0.23 pitfalls we hit along the way (crypto provider installation, SNI construction for direct IP connections, clock skew around certificate validity) are written up separately in the blog post "LAN TLS without a CA".

Incremental sync & conflict merging

Full mutual transfers are wasteful, so VinePalmaFlow computes a content fingerprint for each project (project.md plus the sorted task files, hashed with a hand-written FNV-1a). Sync first exchanges fingerprint tables: identical projects are skipped, and only the differing ones transfer. Merging is three-way: each device directory keeps the baseline mirror from the previous sync; local, remote and baseline are compared — one-sided changes are adopted outright, and a conflict is declared only when both sides edited the same field.

A finer layer is field-level merging of project.md: if device A changed the progress while device B changed the body, a whole-file comparison would misjudge it as a conflict — but merging the YAML fields three-way one by one fuses both changes into one automatically. True conflicts enter the UI for the user to pick a side, and the choice is written back into the baseline mirror — otherwise the same conflict resurrects infinitely at the next sync.

Export: Excel is not the destination, it's the entrance

Export is implemented with rust_xlsxwriter, and import reads back with calamine. We weren't satisfied with "dump the task table into Excel": the overview sheet carries conditional formatting (done green, in-progress yellow, overdue red) and the progress column uses a percentage number format; more crucially, the 4th sheet embeds the complete YAML Front Matter and the original Markdown — export, then import, and zero information is lost: a lossless round trip in the true sense. CSV and JSON are supported too, plus HTML rendered with pulldown-cmark (handy for printing to PDF from a browser).

Peripheral capabilities

Templates: built-in templates such as software development and a customer-follow-up funnel; the list-type fields a template defines are stored in custom_fields and auto-extracted when exporting task details. Full-text search: linear scan + case folding — fast enough at the scale of a few hundred projects per machine. Change log: field-level diffs appended, kept for 30 days with a 2000-entry cap; every save auto-generates a snapshot of the previous version, and together with the trash, mistaken deletes and edits always have a way back.

Engineering trade-offs

The PRD originally planned a tokio async stack; when it came to actually shipping we chose std::thread + the synchronous tungstenite — for single JSON request-responses and a device count in the single digits, dragging in an async runtime just isn't worth the complexity. Similar trade-offs run through the whole project: no apt crate, no YAML crate for serialization (a hand-written idempotent output with fixed field order), no async mDNS (the zero-conf crate's blocking API). The beauty of Rust is that none of these "downgrades" sacrifice type safety.

Closing words

VinePalmaFlow is still iterating fast; a Bluetooth fallback channel and more templates are on the roadmap. If you're fed up with handing your task lists to somebody else's server, give this vine — growing only on your own devices — a try: where your data lives, there your peace of mind lives too.
