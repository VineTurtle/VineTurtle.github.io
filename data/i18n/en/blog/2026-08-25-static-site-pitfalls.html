Grapeleaf's cozy little corner (GrapeLeafi) is the project we've maintained the longest: a pure-static fan site with no framework, no build, no backend. Precisely because "anyone can edit it", a pile of classic static-site bugs accumulated over the years. Each of these four pitfalls is so simple it hardly deserves mention — and each one genuinely survived in production for a long time.

Pitfall one: the "birthday today" branch that never fired

The site has a character-birthday reminder feature, and the code clearly contains a celebration branch:

if (diffDays === 0) {
    // 🎉 今天生日！撒花
}

But this branch never executed. The root cause is in the upstream date comparison:

birthdayDate.setFullYear(today.getFullYear());
if (birthdayDate < today) {      // ← 问题在这
    birthdayDate.setFullYear(today.getFullYear() + 1);
}
const diffDays = Math.ceil((birthdayDate - today) / 86400000);

today is new Date() — carrying the current time (say 14:30), while birthdayDate is set to the birthday's midnight. On the birthday itself, midnight is necessarily earlier than 14:30, so the date gets pushed to next year, diffDays becomes 364 — "today" forever displays as "364 days to go". A classic confusion of comparing a "moment" with a "date". The fix: zero both sides to that day's midnight, then check whether they are the same day:

const startOfToday = new Date();
startOfToday.setHours(0, 0, 0, 0);
const isToday = birthdayDate.getTime() === startOfToday.getTime();

Pitfall two: the QR code that never pops up on phones

The QQ group QR code used a pure-CSS approach:

.qrLinkContainer:hover #qrCodeContainer { display: block; }

On desktop the experience is flawless, but touch devices have no hover — phone users tap the button and nothing happens; the join-group entrance simply vanishes. A natural blind spot of pure-CSS interaction. The fix: add a click/touch class-toggle fallback, or use the native <details> element for "click to reveal" — it works on touch screens with zero JS.

Pitfall three: GitHub Pages, case sensitivity & special-character 404s

The asset directory carried legacy naming: tuan-zi/团子 (1).ico — Chinese, spaces and parentheses, the full trio; the favicon reference had to be written as 团子%20(1).ico. Local preview on Windows is all fine (NTFS is case-insensitive); push to GitHub Pages (Linux servers, case-sensitive) and any casual "let me just change the case of that path" batch-404s. The lesson: static-site asset filenames are lowercase ASCII with hyphens, period; Chinese asset names get renamed at import. And leftovers of historical renames — like tuan-zi/ and tuanzi/ coexisting — deserve an early cleanup too.

Pitfall four: a CDN @latest is a time bomb

The Live2D mascot was included like this:

<script src="https://fastly.jsdelivr.net/gh/stevenjoezhang/live2d-widget@latest/autoload.js" defer></script>

@latest means that with every upstream commit, your site is drawing a lottery: if upstream changes the interface, the site-wide mascot vanishes on the spot — and you may never know. Third-party CDN assets on a static site must pin a version number, even a commit hash. By the way, the site's countdown used setInterval(update, 86400000) to refresh once a day — leave the page open across midnight and it shows stale data; refreshing every minute, or listening for visibilitychange (update when the page becomes visible again), is steadier.

📝 Closing notes

What the four pitfalls share: they can never be reproduced on the developer's own machine. The birthday bug only appears on the birthday itself; the hover issue only on touch screens; the case-404 only on Linux servers; @latest only explodes when upstream updates. A static site may be small, but its test matrix spans time, devices and operating systems. The right way to maintain an aging site is to record these "rookie" pitfalls one by one — they are the cheapest teachers you'll ever get.
