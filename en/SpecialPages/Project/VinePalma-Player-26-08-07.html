VinePalma Player: a local video player

🚧 In progress📅 2026
#Linux#Tauri#Media player

Linux offers plenty of media players, but in day-to-day use you keep finding bugs, big or small — none fatal, yet each one chipping away at the experience.

So the VineTurtle Studio dev team designed and built a local player with Tauri + FFmpeg, cutting memory footprint while still covering everyday audio and video playback.

Background and goals

Traditional desktop players lean on heavyweight frameworks like Electron and casually occupy hundreds of MB of memory, while stock system players lack thoughtful interaction details. We wanted a local player that is light, good-looking and works out of the box: a native backend built on Tauri 2 + Rust with a web-technology front end, memory usage far below comparable products; decoding is provided by FFmpeg bundled inside the app, with no dependence on any system-installed ffmpeg package — genuinely ready to run the moment you install it.

Architecture

VinePalma Player's core design is "streamed playback": media files are never shipped to the front end over IPC. Instead, a tiny_http local server listening only on 127.0.0.1 starts on the Rust side and feeds the file to the WebView's native <audio> / <video> elements as an HTTP stream. With full HTTP Range support, smooth seek-bar dragging works on both WebKitGTK and Chromium.

Decoding follows "native first, transcode on demand": any format the WebView engine can play directly (mp3, flac, m4a, mp4 and so on) streams as-is at almost zero cost; only when the player can't decode something (wma, ape, amr and friends) does it call FFmpeg to transcode to WAV and cache it, while video gets remuxed into faststart MP4/WebM and re-encoded to H.264 when necessary — playable on any platform.

Features

Playlists: pick a single file or import a whole folder, with automatic dedup; audio and video are grouped by type, and the slide-out panel lets you switch, delete or clear tracks at any time. Three play modes — list loop, single loop and shuffle — and shuffle even avoids repeating the same track back to back.

Full playback controls: draggable seek bar (with a hover time tooltip, plus a compatibility fix for WebKitGTK's seek-value bug), volume slider and mute toggle, mouse-wheel volume control, and keyboard shortcuts like Space for play/pause and Left/Right to skip 5 seconds.

Video: video files play centered in fullscreen automatically; hovering shows play/pause and content-fullscreen buttons; click pauses, double-click enters fullscreen, and "window fullscreen" and "content fullscreen" are handled as two distinct modes.

Mini player: a NetEase Cloud Music-style desktop card that stays always-on-top, showing cover, title, progress and previous/play-pause/next controls; closing it returns to the main window. Behind this 340×64 little window also hides a hack around WebKitGTK's minimum window height limit.

Themes: 12 built-in palettes that follow the months, switching automatically with the current month; you can also pin a specific month's theme, or craft a custom five-color theme (background, primary, accent, text, secondary) with the color picker in the settings panel and have it applied globally in real time.

Window interaction: frameless transparent window supporting drag to move, minimize, close and always-on-top, with window fullscreen and content fullscreen never fighting each other. Metadata & covers: duration, title, artist and album are read via ffprobe and the embedded cover art is extracted as the album cover; covers load lazily, so importing a folder never parses every cover at once.

Cross-platform & packaging

GitHub Actions builds installers for Linux (deb/appimage), Windows (nsis) and macOS, with Linux shipping both x86_64 and aarch64 architectures. FFmpeg is a trimmed static build: only the demuxers, decoders and a few encoders the player actually needs are kept; Linux and Windows each have their own build scripts, and the binaries ship inside the installers as resources, called from the resource directory at runtime — the system's /usr/bin is never polluted.

Pitfalls we hit

Development surfaced (and resolved) a long list of WebKitGTK ailments: transparent windows treated as fully click-through, minimum window height clamped to about 200px, streams without Content-Length mistaken for "live broadcasts" and unable to seek, and calling play() too early making the audio a "live stream" with a dead seek bar. We had to lean on GTK-level input-region fixes, set_size_request to force window sizes, a raised chunked threshold and similar measures, plus one unified player.log recording every HTTP request, transcode decision and media event — which makes freeze-class debugging tractable.

Closing words

VinePalma Player is at 0.2.0 now. As an open-source project of VineTurtle Studio, we hope it proves that "a local player can be light, modern and elegant". Next up are continued polishing of decode compatibility and a proper cover wall and lyrics. Suggestions on GitHub are always welcome — let's make it better together.
