Linux でソフトをアンインストールするのは、決して気楽な作業ではありません：APT・Flatpak・Snap・Docker・AppImage……ソースごとに異なるコマンドを覚える必要があり、手動インストールのソフトに至ってはパッケージマネージャーの「戸籍」にすら載っていません。さらに厄介なのは、apt purge できれいに消しても、~/.config・~/.cache・~/.local/share には設定ファイルが大量に残留し、積もり積もってディスクを圧迫——なのに返ってくるのは「アンインストールに失敗しました」か「削除済みだが残留あり」の一言だけ、という具合です。

そこで私たち VineTurtle Studio 開発チームは、Tauri + Vue で開発するこの Linux アンインストーラーを設計・開発しました。APT・Flatpak・Snap・Docker・AppImage・APM の 6 大ソースのソフトを 1 つの GUI に統合し、「徹底的に消す」と「絶対に消し過ぎない」のバランスを取ります。

プロジェクトの背景と目標

Linux のソフト生態系は百花繚乱ですが、管理は断片化しています：標準のアプリストアは 1 種類のソースしか管理できない；コマンドラインはソースごとに異なるアンインストール構文の暗記を要求する；Debian 系パッケージは削除後も「rc 状態」（設定ファイルの記録）を残し、Windows のレジストリ残留に近いもので、一般ユーザーにはほぼ手の出しようがありません。一般ユーザー向けの GUI アンインストーラーを目指しました：1 回の走査で 6 大ソースを一望；アンインストールをクリックする前に、まずシミュレーションプレビューで何に影響するかを教える；残留ファイルにチェックを入れて一気にきれいにする——途中にコマンドラインは一切なし、システムコンポーネントも決してむやみに削りません。

技術アーキテクチャ

VinePalmaUninstaller は Tauri 2 をアプリフレームワークとし、フロントは Vue 3 + Vite、バックエンドは Rust がネイティブ能力を提供します。システムと対話する走査・シミュレーション・アンインストールのロジックはすべて Rust 側に書かれています：dpkg-query・flatpak list・snap list・docker images などのコマンドで各ソースのインストール済みソフトを集約し、root 権限が要る操作（apt purge など）は pkexec で動的に権限昇格するため、一般ユーザーでも GUI の中でシステムレベルのアンインストールを完結できます。

バックグラウンドプロセスは tokio の非同期実行に統一し、タイムアウト保護付きで、特定のコマンドが固まっても UI 全体をブロックしません。削除を伴う操作は「サーバーが計画を生成 → フロントでチェック → サーバーがホワイトリスト検証」の流れを踏み、削除可能なパスはサーバーが再生成した計画からのみ供給され、任意のパスを送り込んで誤削除を起こす余地を塞いでいます。

中核能力：6 大ソースの統一走査

APT：dpkg-query でインストール済み全パッケージとサイズ・説明を読み、/var/lib/dpkg/info 配下の .list ファイルの更新時刻からインストール時刻を近似推定し、システムライブラリ・カーネル・依存は既定で非表示。Flatpak と Snap：それぞれのパッケージマネージャーを呼んでアプリを列挙し、インストール時刻とサイズはアプリディレクトリと snap ファイルのメタデータから解析。Docker：ローカルイメージを走査し、イメージサイズと作成時刻を解析、アンインストール時はそのイメージを参照するコンテナを先に自動削除。AppImage と手動インストール：パッケージマネージャーに登録のない類いなので、~/Applications・/opt などの定番ディレクトリの AppImage ファイルを走査し、.desktop ランチャーの Exec が手動インストールパスを指すエントリと組み合わせて識別します。APM（Amber Package Manager）：コンテナ内の dpkg ステータスファイルからインストール情報を解析し、/usr/local/share/applications 配下の「apm run <pkg>」形式のデスクトップエントリで、UI の起動項目とコンテナ内データを一対一に対応付けます。

リスク等級とユーザーレベルフィルタ

危険度の判定は「パッケージ名の当てずっぽう」ではなく、/var/lib/dpkg/status と extended_states の実データを直接解析して行います：各パッケージがインストール済みパッケージから逆依存されている数を数え、Essential と required 優先度のシステム生命線コンポーネントをマーキング。このデータをもとに、すべてのソフトに low / medium / high / critical の 4 段リスクラベルが付きます。Essential または required 優先度はコア（critical）、8 個以上のパッケージから依存されているものは高リスク、GUI アプリは既定で低リスク。UI の既定「簡易モード」はユーザーレベルのソフト（GUI エントリを持つパッケージ）だけを表示し、システムライブラリ・カーネル・コマンドラインツールは一律非表示。「詳細モード」で全ソフトとリスク等級が現れ、アンインストール前には目立つリスクバナーと連鎖影響の警告が出ます。

アンインストール計画：まずプレビュー、それから実行

アンインストールをクリックしても、コマンドを直接叩くのではありません。まずサーバーが完全なアンインストール計画を生成します：apt パッケージには apt-get purge をシミュレーションモードで実行して削除対象のパッケージリストを解析——関連コンポーネントが連れて削除される場合は「関連パッケージ N 件も合わせて削除します」と計画内で明確に警告。実行時は AutomaticRemove=0 オプションを付け、apt に依存の自動連鎖削除は一切許さず、対象パッケージそのものだけに触れます。計画には実行される全コマンドと認可の要否も列挙され、残留ファイルは設定 / キャッシュ / データ / システムに分類表示——チェックしたものだけ削除、しなければ保持で、ユーザーが一歩一歩完全に掌握します。

残留清掃と孤児依存

「アンインストールが徹底しない」痛みに対して、2 つの仕掛けを作りました。1 つは、dpkg でアンインストール済みなのに設定記録を残す「rc 状態」パッケージを識別し、dpkg --purge 一発で残留記録をきれいに消すこと。もう 1 つは、ソフトごとに定番の独立ディレクトリ（~/.config・~/.cache・~/.local/share・~/.local/state・~/Applications・/opt）を走査し、「パッケージ名バリアントマッチ」でそのソフト自身の設定ディレクトリを特定すること——大小文字を区別せず、ハイフン/アンダースコアを等価扱いするため、既定パスの衝突を避けるために「名前を変えて隠れる」保存先も見逃しません。完全一致したディレクトリは既定でチェック、「含む」関係のあいまい一致は既定で未チェック、無関係なソフトは絶対に誤削除しません。さらに孤児依存の清掃も内蔵：autoremove が削除するパッケージを先にプレビューし、確認後に実行します。

安全設計：絶対に誤削除しない

ファイルを削除するツールとして、安全性は最低ラインです。「計画イコールホワイトリスト」の仕組みに加え、バックエンドには多層の防御があります：FORBIDDEN パス表が /・/home・/etc・/usr・/var などのシステム要諦ディレクトリと直系の子ディレクトリを阻止；home 配下の .config・.cache・.local などの保護ルートの削除を拒否；.. などの危険なコンポーネントを含むパスを拒否。「ユーザー設定を保持」「システム設定を保持」の 2 つの保護スイッチも備え、チェックされたパスがシステムディレクトリに落ちていれば即座に除外します。アンインストール完了のたびに dpkg データベースキャッシュを再読み込みし、再インストールしたソフトも正しく識別され、UI のデータが古くなることはありません。

体験の細部

UI はダークテーマ：リストは名称 / インストール時刻 / 容量 / リスク等級でソートでき昇順降順を切替、キーワード検索とソース別フィルタに対応。各ソフトは dpkg のファイルリスト・アイコンテーマ・Flatpak/Snap のエクスポートディレクトリ、ひいては APM コンテナ内のアイコンツリーから、本物のアプリアイコンを解析しようとします。上部には現在のディストリビューションとアーキテクチャを表示、残留ページには独立した件数バッジ、操作完了には Toast フィードバックと自動リスト更新。アイコン解析には多段キャッシュとバッチロードも施し、数千パッケージの走査でももたつきません。

踏んだ落とし穴

開発では Linux 生態系の落とし穴をかなり踏みました：apt-get のシミュレーション出力にはバージョンによって「Removing」と「Purg」の 2 種の接頭辞があり、両方の互換解析が必要；purge と --no-install-recommends の組合せは「not understood」エラーを出すため、引数順とオプションの調整が必須；dpkg 出力のパッケージ説明に改行が埋め込まれて解析が崩れることがある；docker イメージサイズは GB/MB 接尾辞付き、flatpak の size は桁区切り付きで、それぞれ個別のパーサーを書く必要があった；アイコンのあいまいマッチは汎用ディレクトリ名の誤ヒットに注意し、3 文字未満のアイコン名は一律マッチ対象外。これらの落とし穴はすべてユニットテストで固定し、リグレッションの防壁にしています。

クロスプラットフォームとパッケージング

プロジェクトは Tauri 2 ベースで、パッケージ成果物は deb と AppImage。前者は libwebkit2gtk-4.1 と libgtk-3 の依存を宣言し、カスタムのデスクトップエントリテンプレートも同梱します。フロントは Vite でビルド、Rust バックエンドはネイティブバイナリへコンパイル。アプリ全体は起動が速くメモリ占有も低く、Electron のような重いランタイムには依存しません。

おわりに

VinePalmaUninstaller は現在 1.0.0。VineTurtle Studio のオープンソースプロジェクトとして、次のことを証明したい：Linux のソフト削除も、モバイルのように直感的で安全で後腐れのないものにできると。今後はより多くのディストリビューションとパッケージマネージャーのサポート拡大、残留識別のカバレッジ拡充を予定しています。GitHub でのご提案を歓迎します。一緒にさらに良いものにしましょう。
