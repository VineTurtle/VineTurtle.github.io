Electron on Linux: the icon pitfalls, from packaging to the taskbar

📅 Jul 22, 2026⏱ ~12 min read
#Tech notes#Electron#Linux

While developing the Linux build of VinePalma Player, I recently hit an icon problem that looked trivial yet bothered me for ages. After installation the app icon displays correctly, but the taskbar icon at runtime shows the default "blank" state. This post records the pitfalls I stepped on and the final fix.

📦 The problem

After packaging the Linux build (deb/AppImage) with electron-builder, the icon shows fine at install time — the launcher menu and the app list both look right. But the moment the app runs, the taskbar shows the system's default blank icon

At first I suspected the icon file itself, but inspection showed:

  • ✅ the installed .desktop file has the correct Icon field
  • ✅ the icon file exists in the install directory
  • ✅ the launcher menu icon renders fine
  • ❌ the taskbar icon at runtime is blank/default

🔍 Root cause

Linux desktop environments (GNOME, KDE, XFCE and so on) use the WM_CLASS property to associate running windows with .desktop files. If the window's WM_CLASS doesn't match the .desktop file's StartupWMClass, the desktop environment can't tell which app the window belongs to, and the taskbar icon falls back to the default.

Electron's WM_CLASS is derived by default from the package.json desktopName field. A misconfigured value breaks the association.

🛠️ The fix

1. Icon directory layout

On Linux the icon should point to a folder, not a single file. electron-builder handles the multi-size icons inside automatically:

assets/icons/linux/
├── 16x16.png
├── 32x32.png
├── 48x48.png
├── 128x128.png
├── 256x256.png
└── 512x512.png

Configure it like this in package.json:

"linux": {
    "icon": "assets/icons/linux",  // ← 指向文件夹，不是文件！
    "target": ["deb", "AppImage"],
    "category": "AudioVideo",
    "syncDesktopName": true
}

2. The right desktopName

This is the most crucial step. The desktopName value must not carry the .desktop suffix, or WM_CLASS resolution goes wrong:

// ❌ 错误
"desktopName": "com.vinepalma.player.desktop"

// ✅ 正确
"desktopName": "com.vinepalma.player"

The key parts of the fixed package.json:

{
  "name": "vinepalma-player",
  "desktopName": "com.vinepalma.player",  // 去掉 .desktop 后缀
  "build": {
    "appId": "com.vinepalma.player",
    "productName": "VinePalma",
    "linux": {
      "icon": "assets/icons/linux",
      "target": ["deb", "AppImage"],
      "category": "AudioVideo",
      "syncDesktopName": true
    }
  }
}

3. Main process adjustments

In src/main/index.js, don't call app.setDesktopName() manually — let Electron read the configuration from package.json on its own. If you truly must set it, use the correct format:

// ❌ 不要这样写
app.setName('VinePalma');
app.setDesktopName('com.vinepalma.player.desktop');

// ✅ 推荐：删除手动设置，让 electron-builder 自动处理
// 或确保名称一致
app.setName('com.vinepalma.player');

4. Window icon

Although the taskbar icon is mainly decided by the WM_CLASS association, it's still wise to set a window icon when creating the BrowserWindow, for compatibility across desktop environments:

const path = require('path');

function createWindow() {
    const iconDir = path.resolve(__dirname, '../../assets/icons');
    let windowIconPath;

    if (process.platform === 'darwin') {
        windowIconPath = path.join(iconDir, 'VinePalma.icns');
    } else if (process.platform === 'win32') {
        windowIconPath = path.join(iconDir, 'VinePalma.ico');
    } else {
        // Linux: 使用具体尺寸图片
        windowIconPath = path.join(iconDir, 'linux/256x256.png');
    }

    const mainWindow = new BrowserWindow({
        width: 500,
        height: 520,
        title: 'VinePalma',
        icon: windowIconPath,  // 设置窗口图标
        // ... 其他配置
    });
}

5. Verify the .desktop file

After packaging and installing, check the generated .desktop file (at /usr/share/applications/com.vinepalma.player.desktop):

[Desktop Entry]
Name=VinePalma
Exec=/opt/VinePalma/vinepalma-player
Icon=com.vinepalma.player
StartupWMClass=com.vinepalma.player  // ← 必须与 WM_CLASS 一致
Type=Application
Categories=AudioVideo;

6. Verify WM_CLASS

Run the app, then execute the following in a terminal:

xprop | grep WM_CLASS
// 然后点击应用窗口，查看输出

Expected output:

WM_CLASS(STRING) = "com.vinepalma.player", "com.vinepalma.player"

If StartupWMClass matches WM_CLASS, the taskbar icon displays correctly.

📝 Takeaways

Electron Linux icon issues usually aren't about the icon file itself — they're about the window association mechanism. The essentials:

  • 📁 point the Linux icon config at a folder containing multi-size PNGs
  • 📝 desktopName must not carry the .desktop suffix
  • 🔗 make sure StartupWMClass and WM_CLASS match exactly
  • 🖼️ set the icon property explicitly when creating the window
  • 🚫 avoid manual app.setDesktopName() calls — let electron-builder handle it

I hope this post helps fellow developers who hit the same problem skip the detours. In Electron cross-platform work, Linux desktop integration is truly the most overlooked — and most trouble-prone — part.
