在linux系統中，可以使用的播放器很多，但在使用過程中，經常會或多或少發現一些bug，這些bug雖然不會影響主要功能使用，但在一定程度上會影響體驗。

因此，我們VineTurtleStudio開發組設計並開發了一款本地播放器，使用Tauri+ffmpeg進行開發，在減少記憶體佔用的同時，滿足使用者對音影片播放的需求。

專案背景與目標

傳統桌面播放器往往依賴 Electron 之類的重型框架，動輒佔用數百 MB 記憶體；而系統自帶的播放器又缺乏一些人性化的互動細節。我們希望打造一款輕量、美觀、開箱即用的本地播放器：基於 Tauri 2 + Rust 構建原生後端，前端使用 Web 技術，記憶體佔用遠低於同類產品；解碼能力則由打包進應用內的 FFmpeg 提供，不依賴系統安裝的 ffmpeg 包，真正做到開箱即用。

技術架構

VinePalma Player 的核心設計思路是"流式播放"：媒體檔案並不通過 IPC 傳輸到前端，而是在 Rust 側啟動一個僅監聽 127.0.0.1 的 tiny_http 本地服務，將檔案以 HTTP 流的方式餵給 WebView 的原生 <audio> / <video> 元素播放。配合完整的 HTTP Range 支援，在 WebKitGTK 和 Chromium 上都能實現流暢的拖拽進度條。

解碼策略遵循"原生優先、按需轉碼"：凡是 WebView 引擎能夠直接播放的格式（如 mp3、flac、m4a、mp4 等），直接以原始檔案流式播放，幾乎零開銷；遇到播放器無法解碼的格式（如 wma、ape、amr 等），才呼叫 FFmpeg 轉碼為 WAV 並快取，影片則統一重封裝為帶 faststart 的 MP4/WebM，必要時重新編碼為 H.264，保證任何平臺都能播放。

功能特性

播放列表：支援選擇單個檔案或匯入整個資料夾，自動去重，按型別區分音訊與影片，側滑面板隨時可切換、刪除、清空曲目。播放模式支援列表迴圈、單曲迴圈、隨機播放三種，隨機模式還會避免連續播放同一首。

完整的播放控制：進度條拖拽（懸停時顯示時間提示，並針對 WebKitGTK 的進度條取值 Bug 做了相容處理）、音量滑桿與靜音切換、滑鼠滾輪調節音量，支援空格播放/暫停、左右方向鍵快進快退 5 秒等快捷鍵。

影片支援：影片檔案自動全螢幕置中播放，懸停顯示播放/暫停與內容全螢幕按鈕，點按暫停、雙擊全螢幕，並區分「視窗全螢幕」與「內容全螢幕」兩種模式。

迷你播放器：仿網易雲的桌面小卡片，始終置頂，顯示封面、標題、進度與上一首/播放暫停/下一首控制，點選關閉即可返回主視窗。這一張 340×64 的小視窗背後還藏著一個 WebKitGTK 的最小視窗高度限制 Hack。

主題系統：內建 12 套跟隨月份的配色主題，預設按當前月份自動切換；也可以手動指定某個月份的主題，或使用設定面板中的取色器自定義一套五色主題（背景色、主色調、強調色、文字色、輔助色），並即時應用到全域性。

視窗互動：無邊框透明視窗，支援拖拽移動、最小化、關閉、視窗置頂，視窗全螢幕與內容全螢幕互不干擾。後設資料與封面：通過 ffprobe 讀取時長、標題、歌手、專輯等資訊，並提取內嵌封面圖作為專輯封面，封面採用惰性載入，匯入資料夾時不會一次性解析全部封面。

跨平臺與打包

專案通過 GitHub Actions 構建 Linux（deb/appimage）、Windows（nsis）和 macOS 三種平臺的安裝包，Linux 還同時構建 x86_64 與 aarch64 架構。FFmpeg 採用精簡靜態編譯：只保留播放器需要的解封裝、解碼器與少量編碼器，Linux 與 Windows 各有獨立的構建指令碼，二進位制隨安裝包作為資源分發，執行時從資源目錄呼叫，絕不汙染系統的 /usr/bin。

踩過的坑

開發過程中遇到並解決了大量 WebKitGTK 的疑難雜症：透明視窗會被視為完全點選穿透、視窗最小高度被限制在約 200px、無 Content-Length 的流會被當作"直播流"導致無法 seek、提前呼叫 play() 會把音訊當成直播導致進度條不可用等。為此我們不得不借助 GTK 層的輸入區域修復、set_size_request 強制設定尺寸、提高 chunked 閾值等方案，並用一個統一的 player.log 記錄每次 HTTP 請求、轉碼決策與媒體事件，方便排查凍結類問題。

結語

VinePalma Player 目前處於 0.2.0 版本，作為 VineTurtleStudio 的開源專案，我們希望通過它證明"本地播放器也可以輕量、現代又優雅"。後續計劃繼續打磨解碼相容性、完善封面牆與歌詞功能，歡迎大家在 GitHub 上提出建議，一起把它做得更好。
