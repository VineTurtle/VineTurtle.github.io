VinePalmaFlow の標語は「永遠にクラウドに上げない、でも LAN の中では雲のように協働」。Local-first（ローカル優先）のプロジェクト管理デスクトップアプリで、Tauri 2 + React + Rust で構築しています。アカウント登録ゼロ、アップロードゼロ、すべてのプロジェクトデータは自分のデバイスの中だけ。2 台のデバイスが同じ LAN にいるときは、暗号化ペアリングで増分同期を実現——クラウドの体験を、クラウドのプライバシーコストなしで。

設計哲学：Markdown ファイルがそのままデータベース

ほとんどのプロジェクト管理ツールはデータを専用データベースに閉じ込めますが、VinePalmaFlow の唯一の事実源は人間が読める Markdown ファイルです。プロジェクトは 1 個のフォルダ：project.md が YAML Front Matter でメタデータ（名称・状態・担当者・期限・進捗・タグ・カスタムフィールド……）を記述し、本文は普通の Markdown。tasks/ ディレクトリではタスク 1 件が 1 個のアトミックファイル。添付・テンプレート・バックアップ・ごみ箱はそれぞれ所定の場所に収まっています。万一ある日 VinePalmaFlow をアンインストールしても、これらのファイルはどのエディタでも開け、Git で管理でき、スクリプトで一括処理できます。

初心者はフォーム操作だけで完結し、Front Matter の存在すら知らなくて構いません。上級者はファイルを直接編集すれば、アプリが忠実にパースして戻します。フォームとテキスト、2 つのメンタルモデルが同じ一つのデータを指します。

LAN 同期：mDNS 探索 + TLS 暗号化 + 6 桁のペアリングコード

同期はこのプロジェクトで最も技術密度の高い部分です。デバイス探索は mDNS ベース（サービス種別 _localflow._tcp.local.、既定ポート 4485）、トランスポートは TLS 1.3 上の WebSocket。難所は、LAN の中には CA もドメイン名もないこと——デバイスの身元は自己署名証明書で担い、本当の認証はアプリケーション層へ下ろしました。2 台のデバイスがそれぞれの画面に 6 桁のペアリングコードを表示し、互いに相手の画面のコードを入力、双方向の照合が通って初めて相手を信頼リストへ書き込みます。以後の接続では、サーバー側が相手の TLS クライアント証明書からデバイス ID を取り出し、信頼リストにない ID の push はすべて拒否——メッセージ本文に偽の身元を仕込んでも関所は通れません。

道中で踏んだ rustls 0.23 の落とし穴（crypto provider のインストール、IP 直接接続の SNI 構築、証明書有効期限の時計ずれ）は、ブログ『CA のない LAN で双方向 TLS を実現する方法』に独立した記事として書きました。

増分同期と競合マージ

全量の相互転送はもったいないので、VinePalmaFlow はプロジェクトごとに内容指紋（project.md + ソート済みタスクファイル、手書き FNV-1a ハッシュ）を計算します。同期ではまず指紋表を交換し、同じものはスキップ、差分のあるプロジェクトだけを転送。マージはスリーウェイ方式：各デバイスのディレクトリには前回同期時のベースラインミラーを保存し、ローカル版・相手版・ベースライン版の三者を比較——片側だけの変更はそのまま採用し、双方が同じフィールドを変更したときだけ競合と判定します。

さらに細かい層が project.md のフィールド単位マージです。A デバイスが進捗を、B デバイスが本文を変えた場合、ファイル全体の比較では誤って競合と判定されますが、YAML フィールドを一つずつスリーウェイマージすれば、両方の変更は自動的に 1 つへ統合できます。本当の競合だけが UI に入り、ユーザーがどちらかを選び、その選択はベースラインミラーにも書き戻されます——さもないと、同じ競合が次の同期で無限に復活します。

エクスポート：Excel は終点ではなく入り口

エクスポートは rust_xlsxwriter で実装し、インポートは calamine で読み戻します。「タスク表を Excel に放り込む」では満足しませんでした。概要ページには条件付き書式（完了は緑、進行中は黄、遅延は赤）を付け、進捗列はパーセント数値形式。より重要なのは、第 4 シートに完全な YAML Front Matter と Markdown 原文を埋め込んでいること——エクスポートして再インポートしても情報はゼロ損失、真の意味での無損失ラウンドトリップです。CSV・JSON にも対応し、さらに pulldown-cmark で描画した HTML（ブラウザから PDF 印刷するのに便利）もあります。

周辺機能

テンプレートシステム：ソフトウェア開発、顧客フォローのファネルなどのテンプレートを内蔵し、テンプレートが定義するリスト型フィールドは custom_fields に保存、タスク明細のエクスポート時に自動抽出。全文検索：線形走査 + 大文字小文字の折りたたみで、1 台あたり数百プロジェクトの規模なら十分速い。変更ログ：フィールド単位の diff を追記保存し、30 日間保持・上限 2000 件。保存のたびに旧バージョンのスナップショットを自動生成し、ごみ箱と合わせて、誤って削除しても変更しても取り返しがつきます。

エンジニアリングの取捨

PRD では当初 tokio の非同期スタックを計画していましたが、実装の段で選んだのは std::thread + 同期版 tungstenite——1 リクエスト 1 レスポンスの JSON、デバイス数が一桁というシナリオでは、非同期ランタイムの複雑さを持ち込む割に合いません。似たような取捨がプロジェクト全体を貫いています：apt クレートを使わない、YAML クレートをシリアライズに使わない（フィールド順を固定した冪等出力を手書き）、非同期 mDNS を使わない（zero-conf クレートの同期 API）。Rust の良いところは、こうした「ダウングレード」のどれもが型安全性を犠牲にしないことです。

おわりに

VinePalmaFlow はまだ急速な反復開発の途中で、Bluetooth の予備経路やさらなるテンプレートがロードマップに載っています。タスクリストを他人のサーバーに預けるのに疲れたら、自分のデバイスの上だけに生えるこの蔓を試してみてください——データがあるところに、安心感があります。
