VinePalmaUninstaller 軟體開發

🚧 迭代中📅 2026
#軟體開發#Linux#Tauri

在 Linux 系統上解除安裝軟體，從來不是一件輕鬆的事：APT、Flatpak、Snap、Docker、AppImage……不同來源的軟體要記不同的命令，而手動安裝的軟體更是根本不在包管理器的"戶口本"裡。更讓人頭疼的是，即便用 apt purge 解除安裝乾淨，~/.config、~/.cache、~/.local/share 裡仍會殘留一大堆配置檔案，日積月累佔滿磁碟，卻往往只換來一句"解除安裝失敗"或"已解除安裝但殘留未清除"。

因此，我們 VineTurtleStudio 開發組設計並開發了這款 Linux 解除安裝器，使用 Tauri + Vue 進行開發，把 APT、Flatpak、Snap、Docker、AppImage 與 APM 六大來源的軟體統一納入一個圖形介面，在"徹底解除安裝"與"絕不誤刪"之間找到平衡。

專案背景與目標

Linux 的軟體生態百花齊放，卻也帶來了管理的碎片化：系統自帶的應用商店只能管理一種來源；命令列又要求使用者記住各不相同的解除安裝語法；而 Debian 系安裝包解除安裝後遺留的 "rc 狀態"（配置檔案記錄），類似 Windows 的登錄檔殘留，普通使用者幾乎無從下手。我們希望打造一款面向普通使用者的圖形化解除安裝器：一次掃描，六大來源盡收眼底；點選解除安裝之前，先用模擬預覽告訴你會影響什麼；勾選殘留檔案，一併清理乾淨——全程無需命令列，也絕不亂刪系統元件。

技術架構

VinePalmaUninstaller 採用 Tauri 2 作為應用框架，前端使用 Vue 3 + Vite，後端使用 Rust 提供原生能力。所有與系統互動的掃描、模擬與解除安裝邏輯都寫在 Rust 側：通過 dpkg-query、flatpak list、snap list、docker images 等命令聚合各來源的已安裝軟體，需要 root 許可權的操作（如 apt purge）通過 pkexec 動態提權，普通使用者也能在介面裡完成系統級解除安裝。

背景行程統一使用 tokio 非同步執行，並帶有超時保護，避免個別卡死的命令阻塞整個介面；涉及刪除的操作會先走"服務端生成計劃 → 前端勾選 → 服務端白名單校驗"的流程，可刪除的路徑只來自服務端重新生成的計劃，杜絕提交任意路徑造成誤刪。

核心能力：六大來源統一掃描

APT：通過 dpkg-query 讀取全部已安裝包及其大小、描述，並利用 /var/lib/dpkg/info 下 .list 檔案的修改時間近似估算安裝時間，預設隱藏系統庫、核心與依賴；Flatpak 與 Snap：分別呼叫對應包管理器列出應用，安裝時間與大小通過應用目錄與 snap 檔案的後設資料解析；Docker：掃描本機映象，可解析映象大小與建立時間，解除安裝時還會自動先刪除引用該映象的容器；AppImage 與手動安裝：這類軟體沒有包管理器登記，我們通過掃描 ~/Applications、/opt 等常見目錄中的 AppImage 檔案，並結合 .desktop 啟動項中 Exec 指向手動安裝路徑的條目來識別；APM（Amber Package Manager）：從容器內的 dpkg 狀態檔案解析安裝資訊，再通過 /usr/local/share/applications 下 "apm run <pkg>" 形式的桌面入口把介面啟動項與容器內資料一一對應起來。

風險等級與使用者級過濾

我們並非靠"猜包名"判斷危險程度，而是直接解析 /var/lib/dpkg/status 與 extended_states 的真實資料：統計每個包被多少已安裝包反向依賴、標記 Essential 與 required 優先順序的系統生死攸關元件。基於這些資料，每個軟體都被打上 low / medium / high / critical 四檔風險標籤：Essential 或 required 優先順序的包即為核心（critical），被 8 個以上包依賴的為高風險，GUI 應用則預設低風險。介面預設的"簡易模式"只顯示使用者級軟體（有圖形介面入口的包），系統庫、核心、命令列工具一律隱藏；"高階模式"才展示全部軟體並標註風險等級，解除安裝前還會有醒目的風險橫幅與連帶影響警告。

解除安裝計劃：先預覽，再執行

點選解除安裝並非直接執行命令，而是先由服務端生成一份完整的解除安裝計劃：對 apt 包，先以模擬模式執行 apt-get purge，解析出會被移除的包列表——如果會連帶移除其他相關元件，會在計劃中明確警告"還會連帶移除 N 個相關包"；執行時則帶上 AutomaticRemove=0 選項，絕不讓 apt 自動連帶移除依賴，只動目標包本身。計劃中還會列出每一條將執行的命令、是否需要授權，並把殘留檔案按配置 / 快取 / 資料 / 系統分類展示，勾選才刪除、不勾選保留，使用者對每一步都有完全的掌控。

殘留清理與孤兒依賴

針對"解除安裝不徹底"的痛點，我們做了兩件事：一是識別 dpkg 中已解除安裝但留下配置記錄的 "rc 狀態" 包，一鍵 dpkg --purge 徹底清掉殘留記錄；二是為每個軟體掃描常見的獨立存放目錄（~/.config、~/.cache、~/.local/share、~/.local/state、~/Applications、/opt），通過"包名變體匹配"識別出軟體自己的配置目錄——大小寫不敏感、連字元/下劃線等價，避免預設路徑衝突導致的"換名存放"。精確命中的目錄預設勾選，僅"包含"關係的模糊命中預設不勾選，絕不誤刪無關軟體。此外還內建了孤兒依賴清理：先預覽 autoremove 將移除的包，確認後再執行。

安全設計：絕不誤刪

作為一個會刪除檔案的工具，安全性是我們的底線。除了"計劃即白名單"的機制外，後端還有多層防護：FORBIDDEN 路徑表攔截 /、/home、/etc、/usr、/var 等系統關鍵目錄及其直系子目錄；禁止刪除 home 下的 .config、.cache、.local 等受保護根目錄；拒絕含 .. 等危險元件的路徑；支援"保留使用者配置"與"保留系統配置"兩種保護開關，使用者勾選的路徑若落在系統目錄可被即時過濾。每次解除安裝完成後還會過載 dpkg 資料庫快取，確保重灌後的軟體也能被正確識別，介面資料永不過期。

體驗細節

介面採用深色主題：列表按名稱 / 安裝時間 / 佔用大小 / 風險等級排序並可切換升降序，支援關鍵詞搜尋與按來源過濾；每個軟體都嘗試從 dpkg 檔案清單、圖示主題、Flatpak/Snap 匯出目錄乃至 APM 容器內圖示樹中解析出真實的應用圖示；頂部展示當前發行版與架構，解除安裝殘留頁有獨立的數量角標，操作完成後有 Toast 反饋並自動重新整理列表。圖示解析還做了多級快取與批次化載入，掃描上千個包也不會卡頓。

踩過的坑

開發中踩了不少 Linux 生態的坑：apt-get 的模擬輸出在不同版本間存在 "Removing" 與 "Purg" 兩種字首，需要同時相容解析；purge 與 --no-install-recommends 組合會報 "not understood" 錯誤，必須調整引數順序與選項；dpkg 輸出中包描述裡可能內嵌換行導致解析錯亂；docker 映象大小帶 GB/MB 字尾、flatpak 的 size 帶千位分隔符，都需要逐一編寫解析器；圖示模糊匹配要小心泛化目錄名誤命中，短於 3 個字元的圖示名一律不參與匹配。這些坑我們都通過單元測試固化了下來，作為迴歸保障。

跨平臺與打包

專案基於 Tauri 2 構建，打包產物為 deb 與 AppImage，前者聲明瞭 libwebkit2gtk-4.1 與 libgtk-3 的依賴，並提供了自定義的桌面入口模板；前端由 Vite 構建，Rust 後端編譯為原生二進位制，整個應用啟動快、記憶體佔用低，不依賴 Electron 之類的重型執行時。

結語

VinePalmaUninstaller 目前處於 1.0.0 版本，作為 VineTurtleStudio 的開源專案，我們希望通過它證明：Linux 解除安裝軟體也可以像移動端一樣直觀、安全、不留尾巴。後續計劃繼續擴充套件更多發行版與包管理器支援、完善殘留識別的覆蓋面，歡迎大家在 GitHub 上提出建議，一起把它做得更好。
