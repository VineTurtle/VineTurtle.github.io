葡叶酱的温暖小窝（GrapeLeafi）是我们维护时间最长的项目：一个没有框架、没有构建、没有后端的纯静态粉丝站。正因为它「谁都能改」，几年间积累了一堆静态站的典型 bug。这四个坑每一个都简单到不值一提，却又每一个都真实地在线上存活了很久。

坑一：永不触发的「今天过生日」

站点有个角色生日提醒功能，代码里明确写着庆祝分支：

if (diffDays === 0) {
    // 🎉 今天生日！撒花
}

但这个分支从未被执行过。根因在上游的日期比较：

birthdayDate.setFullYear(today.getFullYear());
if (birthdayDate < today) {      // ← 问题在这
    birthdayDate.setFullYear(today.getFullYear() + 1);
}
const diffDays = Math.ceil((birthdayDate - today) / 86400000);

today 是 new Date()——带当前时刻（比如 14:30），而 birthdayDate 被设置为生日的零点。生日当天零点必然早于 14:30，于是日期被推到明年，diffDays 变成 364——「今天」永远显示成「还有 364 天」。这是「时刻」与「日期」比较的经典混淆。解法是把两边都归零到当天零点，再判断是否同一天：

const startOfToday = new Date();
startOfToday.setHours(0, 0, 0, 0);
const isToday = birthdayDate.getTime() === startOfToday.getTime();

坑二：手机上永远弹不出的二维码

QQ 群二维码用的是纯 CSS 方案：

.qrLinkContainer:hover #qrCodeContainer { display: block; }

桌面端体验完美，但触屏设备没有 hover——手机用户点按钮毫无反应，加群入口直接消失。这是纯 CSS 交互的天然盲区。解法是补一个 click/touch 切换 class 的兜底，或者用原生 <details> 元素实现「点开显示」，零 JS 也能在触屏正常工作。

坑三：GitHub Pages 的大小写与特殊字符 404

资源目录里混着历史遗留命名：tuan-zi/团子 (1).ico——中文、空格、括号三件套，favicon 引用不得不写成 团子%20(1).ico。Windows 本地预览一切正常（NTFS 大小写不敏感），一推到 GitHub Pages（Linux 服务器，大小写敏感），任何一次「顺手改个路径大小写」都会批量 404。教训是：静态站资源文件名一律小写 ASCII、连字符分隔，中文素材名在入库时统一重命名。另外目录里 tuan-zi/ 与 tuanzi/ 并存这种「历史改名残留」，也该趁早清理。

坑四：CDN @latest 是定时炸弹

Live2D 看板娘是这样引入的：

<script src="https://fastly.jsdelivr.net/gh/stevenjoezhang/live2d-widget@latest/autoload.js" defer></script>

@latest 意味着上游每次提交，你的站点都在「抽奖」：上游改了接口，全站看板娘原地消失，而你可能毫不知情。静态站引用第三方 CDN 资源必须锁定版本号甚至 commit hash。顺带一提，站点的倒计时用 setInterval(update, 86400000) 每天刷新一次——如果页面跨午夜一直开着，倒计时会显示过期数据；改成每分钟刷新或监听 visibilitychange（页面重新可见时更新）更稳妥。

📝 写在最后

这四个坑的共性：在开发者的设备上永远复现不了。生日 bug 只在生日当天出现、hover 问题只在触屏出现、大小写 404 只在 Linux 服务器出现、@latest 只在上游更新时爆炸。静态站虽小，测试矩阵却横跨时间、设备与操作系统。维护老站点的正确姿势，就是把这些「低级」坑一个个记录下来——它们是最便宜的老师。
