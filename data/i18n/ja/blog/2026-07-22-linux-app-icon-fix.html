VinePalma Player の Linux 版を開発中、一見単純なのに長いこと悩まされたアイコン問題に遭遇しました。インストール後のアプリアイコンは正常に表示されるのに、実行後のタスクバーのアイコンだけは既定の「空白」状態。この記事は、踏んだ落とし穴と最終的な解決策の記録です。

📦 問題の内容

electron-builder で Linux 版（deb/AppImage）をパッケージングすると、インストール時のアイコンは正常——ランチャーメニューもアプリ一覧も問題なし。しかしアプリを起動した途端、タスクバーにはシステム既定の空白アイコンが現れます

最初はアイコンファイル自体の問題かと思いましたが、確認すると：

  • ✅ インストール後の .desktop ファイルの Icon フィールドは正しい
  • ✅ アイコンファイルはインストールディレクトリに存在
  • ✅ ランチャーメニューのアイコンは正常表示
  • ❌ 実行後のタスクバーアイコンだけ空白/既定

🔍 原因分析

Linux デスクトップ環境（GNOME・KDE・XFCE など）は WM_CLASS プロパティで、実行中のウィンドウと .desktop ファイルを関連付けています。ウィンドウの WM_CLASS が .desktop 側の StartupWMClass と一致しないと、デスクトップ環境はウィンドウの所属アプリを正しく識別できず、タスクバーアイコンは既定表示に戻ってしまいます。

Electron の WM_CLASS は既定で package.json の desktopName フィールドから導出されます。設定を誤ると、この関連付けが断裂します。

🛠️ 解決策

1. アイコンのディレクトリ構成

Linux のアイコンは単一ファイルではなくフォルダを指すのが得策です。electron-builder はフォルダ内の複数サイズアイコンを自動処理します：

assets/icons/linux/
├── 16x16.png
├── 32x32.png
├── 48x48.png
├── 128x128.png
├── 256x256.png
└── 512x512.png

package.json ではこう設定します：

"linux": {
    "icon": "assets/icons/linux",  // ← 指向文件夹，不是文件！
    "target": ["deb", "AppImage"],
    "category": "AudioVideo",
    "syncDesktopName": true
}

2. 正しい desktopName の設定

ここが最重要ステップです。desktopName の値には.desktop 接尾辞を含めてはいけません。含めると WM_CLASS の解析が異常になります：

// ❌ 错误
"desktopName": "com.vinepalma.player.desktop"

// ✅ 正确
"desktopName": "com.vinepalma.player"

修正後の package.json の要点：

{
  "name": "vinepalma-player",
  "desktopName": "com.vinepalma.player",  // 去掉 .desktop 后缀
  "build": {
    "appId": "com.vinepalma.player",
    "productName": "VinePalma",
    "linux": {
      "icon": "assets/icons/linux",
      "target": ["deb", "AppImage"],
      "category": "AudioVideo",
      "syncDesktopName": true
    }
  }
}

3. メインプロセスの調整

src/main/index.js では手動で app.setDesktopName() を呼ばないこと。Electron が package.json から自動で読み取ります。どうしても設定が必要なら、正しい形式で：

// ❌ 不要这样写
app.setName('VinePalma');
app.setDesktopName('com.vinepalma.player.desktop');

// ✅ 推荐：删除手动设置，让 electron-builder 自动处理
// 或确保名称一致
app.setName('com.vinepalma.player');

4. ウィンドウアイコンの設定

タスクバーアイコンは主に WM_CLASS の関連付けで決まりますが、BrowserWindow 作成時にウィンドウアイコンを指定しておけば、各デスクトップ環境での互換性が担保されます：

const path = require('path');

function createWindow() {
    const iconDir = path.resolve(__dirname, '../../assets/icons');
    let windowIconPath;

    if (process.platform === 'darwin') {
        windowIconPath = path.join(iconDir, 'VinePalma.icns');
    } else if (process.platform === 'win32') {
        windowIconPath = path.join(iconDir, 'VinePalma.ico');
    } else {
        // Linux: 使用具体尺寸图片
        windowIconPath = path.join(iconDir, 'linux/256x256.png');
    }

    const mainWindow = new BrowserWindow({
        width: 500,
        height: 520,
        title: 'VinePalma',
        icon: windowIconPath,  // 设置窗口图标
        // ... 其他配置
    });
}

5. .desktop ファイルの検証

パッケージングしてインストールしたら、生成された .desktop ファイル（/usr/share/applications/com.vinepalma.player.desktop）を確認します：

[Desktop Entry]
Name=VinePalma
Exec=/opt/VinePalma/vinepalma-player
Icon=com.vinepalma.player
StartupWMClass=com.vinepalma.player  // ← 必须与 WM_CLASS 一致
Type=Application
Categories=AudioVideo;

6. WM_CLASS の検証

アプリを起動した状態で、端末から次のコマンドを実行します：

xprop | grep WM_CLASS
// 然后点击应用窗口，查看输出

期待される出力：

WM_CLASS(STRING) = "com.vinepalma.player", "com.vinepalma.player"

StartupWMClass と WM_CLASS が一致していれば、タスクバーアイコンは正しく表示されます。

📝 まとめ

Electron の Linux アイコン問題は、アイコンファイル自体ではなくウィンドウ関連付けの仕組みに起因するのが普通です。要点：

  • 📁 Linux のアイコン設定は複数サイズ PNG を含むフォルダを指す
  • 📝 desktopName には.desktop 接尾辞を付けない
  • 🔗 StartupWMClass と WM_CLASS を完全一致させる
  • 🖼️ ウィンドウ作成時に icon プロパティを明示指定する
  • 🚫 手動の app.setDesktopName() 呼び出しは避け、electron-builder に任せる

同じ問題に直面した開発者の遠回りが少しでも減ればと思います。Electron のクロスプラットフォーム開発では、Linux のデスクトップ統合こそが、最も見落とされやすく、最も問題を起こしやすい部分です。
