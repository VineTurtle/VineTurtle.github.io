ぶどう葉ちゃんのあたたかなおうち（GrapeLeafi）は私たちが最も長く維持しているプロジェクト：フレームワークもビルドもバックエンドもない純静態ファンサイトです。「誰でも編集できる」がゆえに、数年で静的サイトの典型的なバグが山ほど溜まりました。この 4 つの落とし穴は、どれも語るまでもなく単純でありながら、どれも本番で長く生き延びていた実物です。

落とし穴 1：一度も発火しない「今日が誕生日」

サイトにはキャラクターの誕生日リマインダー機能があり、コードには祝賀分岐がはっきり書かれています：

if (diffDays === 0) {
    // 🎉 今天生日！撒花
}

しかし、この分岐は一度も実行されたことがありません。根因は上流の日付比較にあります：

birthdayDate.setFullYear(today.getFullYear());
if (birthdayDate < today) {      // ← 问题在这
    birthdayDate.setFullYear(today.getFullYear() + 1);
}
const diffDays = Math.ceil((birthdayDate - today) / 86400000);

today は new Date()——現在時刻を含んでいます（たとえば 14:30）。一方 birthdayDate は誕生日の零時に設定。誕生日当日の零時は必ず 14:30 より早いので、日付は翌年に送られ、diffDays は 364 になります——「今日」は永遠に「あと 364 日」と表示されるわけです。これは「時刻」と「日付」を比較する古典的な混同です。解法は、両辺を当日の零時に合わせてから同一日かを判定すること：

const startOfToday = new Date();
startOfToday.setHours(0, 0, 0, 0);
const isToday = birthdayDate.getTime() === startOfToday.getTime();

落とし穴 2：スマホで永遠に開かない QR コード

QQ グループの QR コードは純 CSS 方案でした：

.qrLinkContainer:hover #qrCodeContainer { display: block; }

デスクトップでは完璧な体験ですが、タッチデバイスには hover がありません——スマホユーザーがボタンを押しても無反応で、参加入口はそのまま消えます。純 CSS インタラクションの宿命的な盲点です。解法は、click/touch で class を切り替えるフォールバックを補うか、ネイティブの <details> 要素で「押して表示」を実装すること。ゼロ JS のままタッチスクリーンでも正常に動きます。

落とし穴 3：GitHub Pages の大小文字と特殊文字 404

リソースディレクトリには歴史遺留の命名が混ざっています：tuan-zi/团子 (1).ico——中国語・空白・括弧の三拍子そろいで、favicon の参照は 团子%20(1).ico と書くしかありません。Windows のローカルプレビューでは万事正常（NTFS は大小文字を区別しない）ですが、GitHub Pages に push した瞬間（Linux サーバーは大小文字を区別する）、パスの大小文字を「ちょっと直した」だけで大量 404 が発生します。教訓：静的サイトのリソースファイル名は一律小文字 ASCII・ハイフン区切りにし、中国語の素材名は取り込み時にリネームして統一します。また、tuan-zi/ と tuanzi/ が併存するような「改名の取り残し」も、早めに掃除すべきです。

落とし穴 4：CDN の @latest は時限爆弾

Live2D 看板娘はこうやって読み込んでいました：

<script src="https://fastly.jsdelivr.net/gh/stevenjoezhang/live2d-widget@latest/autoload.js" defer></script>

@latest は、上流がコミットするたびにあなたのサイトが「ガチャ」を引くという意味です：上流がインターフェースを変えれば、全サイトの看板娘がその場で消え、しかもあなたは気づかないかもしれません。静的サイトがサードパーティ CDN リソースを参照するなら、バージョン番号、さらには commit hash を固定しなければなりません。ちなみに、サイトのカウントダウンは setInterval(update, 86400000) で 1 日 1 回更新していました——ページが真夜中をまたいで開き続けると、期限切れのデータを表示し続けます。毎分更新に変えるか、visibilitychange（ページが再び見えるときに更新）を購読する方が安定です。

📝 最後に

この 4 つの落とし穴の共通点：開発者のデバイスでは永遠に再現できないことです。誕生日バグは誕生日当日だけに出る、hover 問題はタッチデバイスだけ、大小文字 404 は Linux サーバーだけ、@latest は上流更新時にだけ爆発する。静的サイトは小さくても、テストマトリクスは時間・デバイス・OS を横断します。古いサイトを維持する正しい姿勢とは、こうした「初歩的な」落とし穴を一つずつ記録していくこと——それらは最も安価な先生です。
