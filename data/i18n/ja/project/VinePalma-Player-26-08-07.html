Linux には使えるプレーヤーが数多くありますが、実際に使い込むと大小さまざまなバグによく出くわします。主要機能には影響しなくても、体験をそっと削っていくものです。

そこで私たち VineTurtle Studio 開発チームは、Tauri＋ffmpeg で開発するローカルプレーヤーを設計・開発しました。メモリ使用量を抑えつつ、音声・動画再生の日常ニーズを満たします。

プロジェクトの背景と目標

従来のデスクトッププレーヤーは Electron のような重いフレームワークに依存しがちで、数百 MB のメモリを平気で占領します。一方、システム標準のプレーヤーは人間味のあるインタラクション細部に欠けがちです。軽くて美しく、入れてすぐ使えるローカルプレーヤーを目指しました。Tauri 2 + Rust でネイティブバックエンドを組み、フロントは Web 技術——メモリ使用量は同種製品よりはるかに少なく、デコードはアプリ内に梱包した FFmpeg が担うため、システムにインストールされた ffmpeg パッケージに依存せず、文字どおり入れてすぐ使えます。

技術アーキテクチャ

VinePalma Player の中核設計は「ストリーミング再生」です。メディアファイルは IPC でフロントへ運ばず、Rust 側で 127.0.0.1 のみをリッスンする tiny_http ローカルサーバーを立ち上げ、ファイルを HTTP ストリームとして WebView のネイティブ <audio> / <video> 要素へ流し込みます。完全な HTTP Range 対応により、WebKitGTK でも Chromium でもシークバーのなめらかなドラッグが実現できます。

デコード戦略は「ネイティブ優先、必要時のみトランスコード」：WebView エンジンが直接再生できる形式（mp3・flac・m4a・mp4 など）はそのままストリーミング再生し、ほぼゼロコスト。プレーヤーがデコードできない形式（wma・ape・amr など）だけ FFmpeg を呼んで WAV に変換してキャッシュし、動画は faststart 付き MP4/WebM に再コンテナ化、必要なら H.264 に再エンコードして、どのプラットフォームでも再生できるようにします。

機能の特徴

プレイリスト：単一ファイルもフォルダ一括取り込みも対応し、自動で重複排除。種別で音声と動画を分け、スライドパネルからいつでも曲の切替・削除・全消しができます。再生モードはリストループ・1 曲リピート・ランダム再生の 3 種類で、ランダムでは同じ曲の連続再生も避けます。

フルの再生コントロール：シークバーのドラッグ（ホバーで時刻ヒントを表示し、WebKitGTK のシーク値取得バグにも互換対応）、音量スライダーとミュート切替、マウスホイールでの音量調節、スペースで再生/一時停止、左右キーで 5 秒送り/戻しなどのショートカット。

動画対応：動画ファイルは自動で全画面中央再生。ホバーで再生/一時停止とコンテンツ全画面ボタンを表示し、クリックで一時停止、ダブルクリックで全画面。「ウィンドウ全画面」と「コンテンツ全画面」はさらに別モードとして区別されます。

ミニプレーヤー：NetEase Cloud Music 風のデスクトップ小カードで常に最前面。カバー・タイトル・進捗と前へ/再生一時停止/次へコントロールを表示し、閉じればメインウィンドウへ戻ります。この 340×64 の小窓の裏には、WebKitGTK の最小ウィンドウ高制限を回避するハックまで隠れています。

テーマシステム：月ごとに追従する 12 種類の配色テーマを内蔵し、既定で現在月に自動切替。特定月のテーマを手動指定してもよし、設定パネルのカラーピッカーで 5 色テーマ（背景色・主色・強調色・文字色・補助色）を自作して全グローバルへ即時適用してもよし。

ウィンドウインタラクション：枠なし透明ウィンドウで、ドラッグ移動・最小化・閉じる・常に最前面に対応し、ウィンドウ全画面とコンテンツ全画面は互いに干渉しません。メタデータとカバー：ffprobe で長さ・タイトル・アーティスト・アルバムなどの情報を読み取り、埋め込みカバー画像を抽出してアルバムカバーに。カバーは遅延ロードで、フォルダ取り込み時に全カバーを一気に解析しません。

クロスプラットフォームとパッケージング

プロジェクトは GitHub Actions で Linux（deb/appimage）・Windows（nsis）・macOS の 3 プラットフォーム向けインストーラーを構築し、Linux は x86_64 と aarch64 の両アーキテクチャも構築します。FFmpeg は削ぎ落とした静的ビルド：プレーヤーに必要な demuxer・decoder と少数の encoder だけを残し、Linux と Windows はそれぞれ独立したビルドスクリプトを持ちます。バイナリはインストーラーにリソースとして同梱され、実行時にリソースディレクトリから呼び出される——システムの /usr/bin は決して汚しません。

踏んだ落とし穴

開発では WebKitGTK の難問が次々に出てきては解決されました：透明ウィンドウが完全なクリックスルー扱いされる、ウィンドウ最小高が約 200px に制限される、Content-Length のないストリームが「ライブ配信」と誤認されてシーク不能になる、play() を早すぎに呼ぶと音声がライブ扱いになってシークバーが死ぬ——など。そのため GTK 層の入力領域修正、set_size_request によるサイズ強制、chunked 閾値の引き上げといった手段に頼ることになり、さらに統一の player.log で HTTP リクエスト・トランスコード判断・メディアイベントをすべて記録して、フリーズ系問題の切り分けを可能にしました。

おわりに

VinePalma Player は現在 0.2.0。VineTurtle Studio のオープンソースプロジェクトとして、「ローカルプレーヤーも軽量でモダンでエレガントになれる」ことを証明したいと思っています。今後はデコード互換性の継続的な磨き込みと、カバー壁・歌詞機能の充実を予定しています。GitHub でのご提案を歓迎します。一緒にさらに良いものにしましょう。
